# 00 · 入门总纲

> 本文档是学习和工作材料的入口。当前目标以 2026-09-23 的最新对齐为准；较早的 AllToAll/EP 调研保留为背景，不再代表当前主任务。
> 最后更新：2026-09-23

## 一、当前工作目标

**主线：FT-AllReduce。** 参考 FT-HSDP/FTAR，面向 RoCE 组网下的超节点间通信，提出 fault-tolerant AllReduce 方案，并完成一个范围受控的简单原型验证。

**支撑线：AllReduce 路径洞察。** 以 AllReduce 为切入口，梳理从集合通信接口、HCCL/HCOMM 算法和拓扑，到服务器/超节点互联和 RDMA 网络的路径；调研多层级组网下实现方式的差异，以及万卡、十万卡规模下 AllReduce 的网络路径。对大规模部署结论注明来源和可信度，不把规模直接等同于“必然走 RDMA”。

**阶段性预期成果**：

1. AllReduce 多层级组网与路径洞察文档。
2. RoCE 超节点间 FT-AllReduce 设计方案。
3. 简单原型或 PoC，以及对可行性和主要缺口的总结。
4. 试用期总结和导师汇报材料。

**时间安排**：见 [`08-学习时间线.md`](08-学习时间线.md)。当前先对齐到阶段和预期产出，细化到代码改动、接口和实验的安排放在方案明确之后。

## 二、概念边界

| 概念 | 含义 | 当前关注点 |
|---|---|---|
| **AllReduce** | 所有 rank 对输入执行规约，并获得规约结果 | 不同拓扑层次如何分解和传输 |
| **RDMA / RoCE** | 节点间数据传输技术；RoCE 是以太网上的 RDMA | 某阶段是否使用 RDMA，要由拓扑、配置、通信库和运行证据确认 |
| **超节点** | 由高速互联组织的一组设备/服务器；具体定义依产品组网而异 | 超节点内部和超节点之间分别如何通信 |
| **多层级组网** | 通信域按服务器、超节点、网络域等拓扑组织 | 各层对应的通信阶段、算法和故障边界 |
| **FT-AllReduce** | AllReduce 在参与 rank 或通信链路故障后的检测、停止、恢复/重试机制 | 参考 FTAR，先明确通信层恢复语义和上层职责 |
| **scale-up / scale-out** | 语境相关：可指单系统扩展、集群扩展，也可指弹性运行时增减成员 | 记录时写清所指对象，避免只用术语不说明含义 |

工作区里的 L1/L2/L3 可能分别指软件架构、HCCL 算法通信层级或物理网络拓扑层级；当前尚未确认导师所用的具体口径，应在路径洞察中并列区分并进一步确认。

## 三、学习与研究顺序

1. **基础概念**：集合通信、AllReduce 算法、rank/通信域、RoCE/RDMA 和网络拓扑。
2. **路径洞察**：阅读 HCCL/HCOMM 与 NCCL 相关实现，跟踪 AllReduce 在不同拓扑下的调用与数据路径；调查大规模集群通信设计。
3. **容错机制**：精读 FT-HSDP/FTAR，梳理成员故障、通信恢复与控制面/数据面分工；对照昇腾现有容错机制。
4. **方案与原型**：聚焦 RoCE 超节点间 AllReduce，形成方案并做简单原型穿刺。
5. **总结交付**：将洞察、方案、验证结果和未解决问题整理成可复核材料。

## 五、本阶段已掌握的工作区线索

- HCCL/HCOMM 代码存在按 `COMM_LEVEL0/1/2` 分层组织 AllReduce 的实现路径；具体层级对应关系需结合产品拓扑理解。
- 多超节点 AllReduce 的一个源码路径包含局部 ReduceScatter、超节点间 AllReduce、局部 AllGather，可作为路径学习入口。
- HCOMM 软件架构中的 L1/L2/L3 与 HCCL 算法通信层级不是同一概念。
- 源码里存在 RDMA 与 TCP 等协议路径；具体任务运行时是否走 RoCE/RDMA，需要结合目标硬件、通信配置和运行证据判断。
- 当前没有据本地源码确认任何特定万卡或十万卡集群的实际网络配置。

源码入口与证据整理见 [`11-AllReduce路径洞察.md`](11-AllReduce路径洞察.md)，论文资源和仓库信息见 [`REFS.md`](../REFS.md)。
